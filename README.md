# Ebook Workshop · Kindle 电子书校对和整理 Skill

最近在 Kindle 和电脑上读书，EPUB个人不好编辑校对，而且有些版本是ocr扫描识别出来的，会混进错字、方框和多余换行，排版某些部分也有点问题，过于密集什么的。于是我把自己整理电子书时用到的勘误、排版和换封面方法做成了这个 Skill。

可以搭配 WorkBuddy、Qoder、豆包、Codex 等 AI 助手，也可以自己运行附带的工具（比较麻烦就是）。

## 能做什么

1. **检查内容**：找出疑似空章、重复段落和跳号，按已有标题识别正文、番外、附录与后记。章数不同不一定代表缺内容。
2. **比较版本**：对比两份或更多 TXT、EPUB 的章节结构和相同段落，帮你选底本。默认不展示章名或正文片段。
3. **转换格式**：分两条路，入口不同，别混用。

   - **TXT → EPUB** 用 `build`：把 TXT 做成有可跳转目录的 EPUB，填写你确认的书名和作者，可选封面。
     前置文字、作者留言和后记按原位置保留。`build` 只认 TXT，**不能吃 Word/PDF/EPUB**。
   - **格式互转** 用 `convert`：原生读入 EPUB、DOCX、ODT、HTML（含 `.htm`），
     写出 EPUB、MOBI、AZW3，不需要装 Calibre。Word 用标题样式可以生成可跳转的目录，
     中英文标题样式都认得；旧版 `.doc` 请先另存为 `.docx`。

   写出格式由 `--output` 的扩展名决定；`--format epub|azw3|mobi` 只在没给 `--output` 时生效。
   `.mobi` 是纯 MOBI 6，`.azw3` 是纯 KF8 standalone（不带 MOBI 6 兼容段，很老的设备请改用 `.mobi`）。
   PDF、纯文本扫描件、旧版 `.doc` 等超出原生范围的，装了 Calibre 才会自动交给它，
   没装会明确告诉你缺什么；原生读入失败时也会自动回退 Calibre。

   转出的书自带一套中文小说排版：衬线字体、1.8 倍行距、左右各留 5% 页边距、首行缩进两字、段间半行空、章节标题居中且不与正文分页。EPUB 转 EPUB 时**原书的样式表原样保留**，不会被这套默认排版覆盖；只有原书一张样式表都没有时才补上默认那份。想要更精细的排版，可以再用 `layout` 命令单独套用预设或调参数。
4. **精修已有 EPUB**：直接读取书里的文字，找疑似错字和乱码，按核实过的清单勘误。可以套用我平时用的中文小说排版，也可以自己调页边距、行距、首行缩进和段间距。 校对流程进一步更新：脚本筛查整本书，查错字形近字、繁简与异体字混入、对话引号缺失和异常字符，当前 AI 助手复核重点并修正明确错误；支持子 Agent 时可分给一两个助手处理。使用方法见[校对流程](references/proofreading.md)。
5. **更换封面**：用你提供的图片，或把另一份 EPUB 的封面搬过来。
6. **检查、接通注释**：不同来源的 EPUB 里，注释做法差得很远——有的本来就能点，有的只是正文里的一个圈码，点不动。
   `notes` 会先做体检：注释引用是哪一种、有没有指向不存在锚点的断链、注释正文有没有标上 EPUB 3 语义、
   圈码能不能和注释正文对上号；报告只给位置和引用标记，不展示注释正文、不剧透。
   `notes-fix` 把接不上的接上，给已有链接补 `epub:type="noteref"`、给注释正文补 `epub:type="footnote"`，
   **正文文字一个字不改**。

   圈码配对只对序列完全一致的高置信组动手；底本自己写错编号的那几组列进报告留给人判断，
   宁可少改也不把注释链到错的段落上。完整规则见 [注释说明](references/notes.md)。
7. **准备 Kindle 阅读**：邮件传书可准备 EPUB，按需加估算页码；USB 可直接生成 AZW3，不需要 Calibre。我手动检查目前是没看出问题。

整理时保留原文件。默认另存到原文件旁的 `整理后` 文件夹，EPUB 文件名用标准书名，例如 `书名.epub`。
`notes` 是唯一连输出文件都不写的命令。

## 怎么用

### 1. 下载

[点击下载](https://github.com/Arisgod1/ebook-workshop/archive/refs/heads/main.zip)，解压后保留整个文件夹。

### 2. 交给 AI 助手

如果你的助手支持导入 Skill，按它的安装方式导入；也可以直接让它打开这个文件夹，读取其中的 `SKILL.md`。

助手会自动准备校对环境，尝试安装 Jieba 大词库；安装失败时仍可继续整理，无需你手动处理。脚本负责找出疑点，同一种错字只复核一次，最后由 AI 助手统一修改。

助手需要能读取电子书并运行处理工具。只有聊天功能时，可以让它给出操作步骤，由你在电脑上执行。

### 3. 告诉它你的需求

例如：

> 请按照这个项目的 SKILL.md 帮我整理电子书。比较这两份文件的正文和番外，默认不要剧透，选更合适的一版做成 EPUB。使用我指定的封面，书名和文件名保持标准写法。我要在 Kindle 上阅读，通过邮件传书，希望能显示页码。

也可以只做一件事：

> 把这本 TXT 转成带封面的 EPUB，保留正文、番外和后记。

> 把另一份 EPUB 里的封面搬过来，正文不变。

> 整理这本书的段落和目录，让它在阅读器上看起来更舒服。

> 用中文小说预设整理这本 EPUB，检查明显错字和杂音，保留现有页码。

> 检查这本书的注释能不能点，接不上的帮我接上，别改正文。

> 先看注释体检报告，把断链和圈码对不上的地方列出来，先别动手。

`notes` 只报告、`notes-fix` 才输出新书；若底本编号本身有错，报告会列出待人工确认的条目，
不会自动猜改。[注释说明](references/notes.md) · [命令](references/commands.md#注释体检与规范化)

中文小说预设适用于可调整字号的 EPUB 3，默认采用左右各 5% 的边距、1.8 倍行距和两字缩进，这些都可以调整。先让助手另存一本，只在其中一章试排，用常用字号打开看看，再决定是否套用到整本书。

[完整精修流程](references/reading-workflow.md) · [试排命令](references/commands.md#套用中文小说排版)

## 不同助手的接入方式

- **WorkBuddy**：通过“上传技能”导入。
- **Qoder 系列**：通过对应产品的 Skills 功能导入，或让它读取项目文件。
- **豆包等对话助手**：提供 `SKILL.md` 和任务文件；能否直接处理取决于当前使用环境。
- **其他 Agent**：读取项目中的 `SKILL.md`，按其中的方法操作。

具体方法见 [接入说明](references/agent-integration.md)。

### 以 Codex 为例

将整个文件夹放到 `~/.codex/skills/ebook-workshop`，随后这样使用：

> 使用 $ebook-workshop 帮我整理这本电子书，制作带封面的 EPUB。

也可以不安装，直接让 Codex 读取项目里的 `SKILL.md`。本项目不依赖 Codex，其他助手按各自的方式接入即可。

## Kindle 页码

可以添加用于记录阅读进度的估算页码。它不对应纸书页数，也不一定每翻一屏就增加一页。

告诉助手你的 Kindle 型号，以及使用邮件还是 USB 传书，它会按对应方式准备。详见 [Kindle 使用说明](references/kindle-pages.md)。

## 想自己操作？

也可以直接使用附带的 Python 工具，操作方法见 [命令参考](references/commands.md)。完整功能清单见 [功能表](references/feature-table.md)。

比如注释这两步，自己跑就是这样：

```bash
# 先体检：只打印 JSON 报告，不写任何文件
python3 scripts/ebook.py notes '原书.epub'

# 确认没问题再规范化：原书不动，另存新文件
python3 scripts/ebook.py notes-fix '原书.epub' --output '整理后/书名.epub'

# 改完再体检一遍，确认断链清零、引用都成了 noteref
python3 scripts/ebook.py notes '整理后/书名.epub'
```

报告里 `broken_links` 最要紧——书能打开但点注释跳不过去，就靠它查出来。
`notes-fix` 不改正文可见文字、不升级 EPUB 版本，重复跑也安全。

扫描件和 PDF 要看是哪种：文字可选中的单栏 PDF 可以交给 `convert` 试转；
**纯扫描 PDF 没有文字层，脚本不会自动识别图片**，得先用外部 OCR 逐页导成 TXT，
再 `ocr-text` 清洗（合并硬换行、去页眉页码）→ `build` 转成带目录的 EPUB →
`proofread` 筛查 OCR 常见的形近字与繁简异体混入。顺序不能跳：`proofread` 只能读 EPUB，
不能直接喂清洗后的 TXT。完整命令见 [扫描件与 PDF 的文字层](references/commands.md#扫描件与-pdf-的文字层)。

想确认这个工具在你的电脑上是否一切正常，可以跑一遍测试：

```bash
python3 -m unittest discover -s tests -t . -v
```

测试用的书、图片和文档全部在运行时现场生成，不需要额外准备。项目只提供整理工具，不附带书籍或封面。
